# AETHERQOR V8 — EXTERNAL RESEARCH REPORT

Date: 2026-09-05. Scope: A1-A5, B1-B6, C1-C3. This report separates authoritative documentation, open-source implementation evidence and community/forum experience. It does not replace local AETHERQOR measurements.

## Executive technical findings

1. **A1 terraces:** after successful Alpha Wrap, the next credible algorithmic class is not another generic decimator but input-domain cleanup plus localized feature-aware fairing/remeshing. CGAL Polygon Mesh Processing exposes mesh fairing, tangential/shape smoothing and constrained/feature-aware operations. This supports a controlled experiment after raw-vs-cropped donor causality is established. It does not prove that global smoothing is suitable for armor.

2. **A2 mosaic:** Blender Pointiness, Marmoset curvature and Substance curvature are geometry-derived signals. This is materially different from the current 2D Gaussian cavity operation that local measurement already proved aliases UV seams as geometry. The first architecture change should therefore be cavity-source replacement, not UV repacking.

3. **A4 hair:** two public URP hair implementations exist with permissive licenses. `itsFulcrum/Unity-URP-Hair-Shader` is CC0 and explicitly uses anisotropic highlight logic plus noise to break highlights; `cathyhlshih/UnityURPAnisoHighlightHairShader` is MIT. Both are useful controlled material references, but the first explicitly describes itself as experimental/older-Unity work. V8 must port minimally and profile Unity 6/mobile.

4. **B2 FBX materials:** Unity provides supported material remapping architecture. `ModelImporter.SearchAndRemapMaterials` searches existing project Material assets and maps them to imported material identifiers. `ImportViaMaterialDescription` delegates imported material interpretation through `OnPreprocessMaterialDescription`. `AssetImporter.AddRemap` can explicitly remap imported sub-assets. This strongly supports making Unity project materials authoritative rather than trusting FBX round-trip material instances.

5. **B3 skinned merge:** this is an established engineering problem. Public implementations and developer discussions show the required data classes: vertices/triangles/UVs, bone weights, bones/bindposes, materials/submeshes and optionally blendshapes. UMA contains a real MIT `SkinnedMeshCombiner`; `lxteo/UnitySkinnedMeshCombiner` demonstrates the concept but has no license metadata and must not be copied. The main AETHERQOR risk is not feasibility but silent skeleton/bindpose/index corruption, so animation regression must be first-class.

6. **B4/B5/C1 identity:** Riot and Valve emphasize stable primary characteristics, silhouette and actual gameplay-view recognition. Neither establishes a universal anchor-height percentage or IoU cutoff. Weapons are a common strong identity carrier because they can create clear external silhouette and motion cues, but AETHERQOR should measure its own class set instead of turning a Garen measurement into a universal rule.

## A1 — feature-aware cleanup after reconstruction

### Authoritative evidence
CGAL Polygon Mesh Processing includes operations for fairing mesh regions, smoothing, feature detection and constrained remeshing. That creates a plausible deterministic toolchain for a *localized* repair pass once the problem region is known.

### Application to AETHERQOR
The correct test order is causal:
- raw donor -> Alpha Wrap;
- semantic torso crop -> same Alpha Wrap settings;
- compare step-height/silhouette/donor error;
- only if donor contains high-frequency tears that must be softened, select terrace region and run constrained/local fairing.

Global fairing risks destroying plate breaks and donor fidelity. Feature edges and max allowed displacement must be constraints, not subjective inspection.

### Video targets
V8 includes clean shell construction/import cleanup and ZBrush hard-surface topology videos as visual workflow evidence. They are not proof that ZRemesher solves soup; that question is already closed.

## A2 — geometry-space curvature and UV seams

### Blender
Geometry `Pointiness` is an approximation of mesh curvature available in Cycles. Because it is geometry-driven, it is useful as an independent control to answer whether the mosaic disappears when the source signal is no longer generated by a 2D texture blur.

### Marmoset
Toolbag's curvature bake derives convex/concave information from mesh geometry and is designed for high-to-low texture baking. This gives an independent production control.

### Substance
Substance's curvature baker is also geometry-driven and exposes seam-related handling. It is another useful control if already available in the toolchain.

### xatlas
`jpcy/xatlas` is MIT, mature and widely used for mesh parameterization/UV unwrapping. It is a candidate only after geometry-space curvature is tested. The objective is not simply lowering `461` but improving final seam/error behavior without unacceptable stretch or texel-density variance.

## A3 — footwear

No external tutorial can identify the AETHERQOR root cause. Production references reinforce one important principle: silhouette-supporting features stay geometry while micro surface detail bakes. Therefore sole/toe/heel should be treated as semantic macro features and tracked through the pipeline. V8 should not regenerate all boots before locating which stage destroys them.

## A4 — hair at real gameplay scale

### CC0 URP implementation
`itsFulcrum/Unity-URP-Hair-Shader` is a hair-card shader for URP. Its own documentation says it is experimental, originally tested on Unity 2021.3, uses normal maps and anisotropic highlight behavior, and includes anisotropic noise specifically to break up highlight reflections. That directly attacks the uncontrolled specular variable in the old Cycles proof.

### MIT alternative
`cathyhlshih/UnityURPAnisoHighlightHairShader` is an HLSL/Shader Graph anisotropic-highlight project under MIT. It gives a second implementation reference.

### V8 implication
Before changing one triangle, compare materials in Unity 6 at actual character heights and motion. If the bright crown facets disappear or become imperceptible at 90–300 px, the prior geometry debt was created by an invalid measurement setup.

## A5 — source anomaly

No generic tool should normalize a 15,208-tri source into the same slot logic as ~1,052-tri peers without asking why. This is a provenance/data validation problem. V8 should make slot-source outlier detection part of the pipeline before reduction. Robust statistics against class/sex slot cohorts are more valuable than a fixed universal triangle threshold.

## B1/C2 — same class across sexes

Riot's clarity guidance says a champion's primary characteristic must remain stable enough for recognition. This favors preserving class macroform/primary feature across body variants even if exact armor shell construction changes. It does not answer the owner's art-direction choice. Engineering should show both options with equal-quality proofs.

Community arguments about 'realistic' versus stylized female armor are not evidence for AETHERQOR. They are intentionally excluded from technical verdicts.

## B2 — deterministic Unity material import

### `SearchAndRemapMaterials`
Unity's ModelImporter API can search existing project materials using material naming conventions and remap imported materials to them. The docs include an AssetPostprocessor example running this in `OnPreprocessModel`.

### `ImportViaMaterialDescription`
In this mode, Unity collects imported material properties into a `MaterialDescription` and allows preprocessing/remapping. URP/HDRP also provide pipeline-specific material conversion behavior.

### Explicit remap
`AssetImporter.AddRemap` allows explicit mapping of source/imported sub-assets to external assets.

### Proposed contract
- stable semantic FBX material slot name;
- project-owned Unity Material GUID/path;
- checked-in manifest;
- deterministic postprocessor remap;
- missing/ambiguous semantic material = import FAIL;
- all 14 characters validated after import.

The existing Blender render rescue flag is no longer acceptable evidence that Unity import is correct.

## B3 — combining modular skinned meshes

### GitHub
**UMA**: MIT, active modular avatar framework; contains a real `SkinnedMeshCombiner`. Strong primary code reference.

**Whinarn/UnityMeshSimplifier**: MIT, Unity mesh simplification/combining project. Useful supporting utilities/reference; applicability to full skinned aggregation must be checked rather than assumed.

**lxteo/UnitySkinnedMeshCombiner**: description explicitly targets Mecanim SkinnedMeshRenderers with bones and blendshapes. No license metadata was exposed, therefore reference-only.

### Forums/community
Unity developers consistently describe the combine operation as assembling vertex/triangle/UV data plus remapping bone weights and bones. Runtime combining is commonly done on character confirmation/equipment change rather than every frame. Community performance claims vary, especially on modern Unity 6, so AETHERQOR must profile before setting renderer-count dogma.

### Important Unity 6 caution
Modern SRP Batcher/compute skinning behavior can change the relative benefit of reducing SMR count. The correct success metric is target-device CPU/GPU/render-thread data, not 'one renderer must always be fastest'. Combine is still valuable when it also consolidates material/submesh state, but measure variants.

## B4/B5/C1 — identity and weapons

Valve's Dota art guide prioritizes immediate recognition from the actual top-down game view and states that weapons should have a unique read and complement the character. Riot's clarity article calls silhouette a primary recognition feature and discusses a stable defining characteristic, e.g. a signature weapon.

The practical AETHERQOR interpretation:
- add a technical weapon slot because architecture currently lacks a valid identity carrier already budgeted in the Bible;
- do not force every class to use a sword or force 68% extent;
- let each class have a primary cue that changes external contour/mass/motion in actual game view;
- calibrate with 7AFC humans instead of pretending IoU 0.85 is external standard.

## B6 — Frost shield

This is almost entirely local forensics. External rigging material only establishes that worn equipment must have a clear parent/attachment relationship. The root cause should be found by comparing transform/bone ownership and distance trajectories to a correct backpiece.

## C3 — visual bands

External material/shader research supports parameter-driven appearance rather than duplicated assets. The unresolved part is perceptual/art direction. V8 should produce controlled renders where exact gameplay rank remains 0–6/1–7 but visible presentation is grouped into 2, 3 or 4 bands. Test daylight because V7 already showed Bloom can collapse night/day discrimination.

## Forum evidence policy

Reddit, Unity Discussions, GameDev.net and Polycount are included to find failure modes and implementation tricks, never to define a production threshold. Any forum claim such as 'combining is free performance' must become an AETHERQOR profiler experiment before use.

## Final V8 standard

No external article, GitHub repository or video is enough by itself. Final acceptance order:
1. authoritative source says technique is valid/supported;
2. video/source code shows how it behaves;
3. local AETHERQOR pilot proves it on real asset;
4. target-scale Unity proof shows visual result;
5. regression/performance metrics show no hidden cost;
6. only then integrate broadly.
